How it sees

Every time the engine asks the network a question, the network gets 298 numbers (413 with the helper inputs below): what this player knows at that moment, plus what is being asked. It answers with 34 numbers: a score for each card (or Sentry option) and one for "pass"; only the legal answers count.

The first 175 are az-v1's features exactly (az_features in az-v1/c/az.c); the rest are new, because this network also plays the action phase, where the hand matters.

Helper inputs (from rl-v2): 115 more

Numbers a good player works out in their head, computed exactly from what the player knows, so the network does not have to learn the arithmetic. The next hand is the first 5 cards of the draw pile (its contents are known, not its order); if fewer than 5 are left, the rest come from everything else reshuffled (discard, hand, in play). During the opponent's turn the next hand is the hand it holds now. The odds are exact (hypergeometric), not simulated.

InputsHow manyWhat
next hand9expected coins; chance of at least $3, $5, $6, $8; expected action cards, +Actions, +Buys, +Cards
next turn's VP2expected VP gain (the best Victory card the next hand can afford: Province at $8, Duchy at $5, Estate at $2, if there are any left) and the VP after it
the whole deck5coins, action cards, +Actions, +Buys and +Cards per 5 cards (an average hand)
if I gain this card3 × 33for every card in the game: how one more copy changes coins, +Actions and +Buys per 5 cards

Example (turn 1, hand Copper ×3 + Estate ×2): the draw pile holds 4 Coppers and an Estate, so the next hand is exactly that: expected coins 4.0, chance of $3+ 100%, of $5+ 0%; the best VP buy at $4 is an Estate (+1 VP). Gaining a Gold would add +1.05 coins per 5 cards, a Silver +0.59, a Province −0.32 (it dilutes the deck).

How they were added. rl-v1's checkpoint read only the first 298 inputs. rl-v3 gave it the 115 helper inputs with zero weights (so at iteration 0 it plays exactly as rl-v1), and training decides what they are worth. rl-v1's champion, which it meets in its league, still reads only the first 298. tests/test_play_parity.py checks that the browser's Python version computes the same numbers as the C engine.

What it does not see

The order of its own draw pile, the opponent's hand, the opponent's draw pile: the engine computes the features from the player's own view, and the order of the draw pile never enters them (only its contents, which a careful human player can count too). Unlike az-v1's search it never imagines hidden cards either: it has no search at all.

The test tests/test_core.py checks that the C forward pass and the PyTorch one agree, and that GA seats in this engine replay az-v1's games exactly.

An example

Turn 6, the opponent just played Militia, I hold Copper, Copper, Estate, Silver, Smithy. The question: "Militia discard" (one of the 22 kinds), asked twice in a row. Inputs: my hand (Copper ×2, Estate, Silver, Smithy), "my turn" = 0, actions = 0. Nobody tells it that Estates are useless in hand: it has to find out from thousands of games in which keeping the Silver and the Smithy led to more wins.
