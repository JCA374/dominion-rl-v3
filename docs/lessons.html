Lessons

What this project and earlier ones taught. Newest first.

From this project

  • A visible mistake is not a costly one. rl-v1's champion picks the coin-best action only 91.6% of the time on the chain exam (76% with Throne Room in hand). Yet a planner that fixes those choices, and a rule that fixes the clearest kind, both scored 48–50% head to head against the plain network. Measure the fix in whole games before building it into the player.
  • A judge must see the whole consequence. Judged by coins this turn, the planner never plays Chapel or Remodel, because trashing costs money now. Judged by the network's win estimate after the turn, it is too noisy to separate two orderings: it once preferred Militia before Laboratory, which can never be better. Both judges failed in opposite ways.
  • Where you cannot see the mistakes, look at the decks. The card audit found what the win rates hid: the champion had never bought Chapel, so it could not learn whether Chapel pays. No error count shows that; only "never asked" does.
  • An unknown card is not a weak card. Given two forced Mines, the champion plays Mine 6.6 times per game without having been taught: the network generalises across cards. What it lacked was the experience of owning one.
  • Check the timing of a gate. Stage 1's gate (84% against the GA genome on 400 evaluation games, ±4%) passed at iteration 20 on one lucky evaluation. A gate on one noisy number moves the curriculum early; a gate on a moving average would not.
  • Test every card in whole games, both engines. Six cards had no hand-made rule test. A per-card whole-game test (bought, played, every question asked, identical in Python and C) now covers all 26.

From rl-v2

  • Give the network the arithmetic. 115 helper inputs (exact next-hand odds, what one more copy would change) lifted a run that had been flat for 400 iterations from 71% to 74% against the GA genome. rl-v3 starts with them.
  • Self-play from zero finds a style early and keeps it: money plus attacks, 0.5 actions per turn, while rl-v1 grew into an engine player (1.6). A teacher's start is a head start here, not a ceiling.
  • Add inputs without starting over: zero weights and zero optimiser state leave play unchanged.

From rl-v1 (this project's parent)

  • You can only beat what you practise against. rl-v1 tied az-v1 head to head until az-v1 joined its league; then it won 55%, and after 2,200 iterations 72%. Here rl-v1's champion joins in stage 2.
  • Speed is a feature. 3 ms per game inside the C engine, against 460 ms for az-v1's search: millions of practice games on a laptop.
  • Confirm once, on games never used, with the rival on the same games. This project has its own never-used confirmation set (experiments/confirm.py, a new seed), for the end.

From az-v1

  • Search over buys saturates at about 70% against the GA genome. rl-v3 adds that search over the action phase does not help either: on this laptop the plain network, trained long, is the strongest method.
